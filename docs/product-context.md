# 해커톤 아카이브 제품 컨텍스트

> 문서 상태: 초기 제품 방향
>
> 이 문서는 제품의 목적과 도메인 기준을 공유하기 위한 자료다. 세부 정책과 MVP 범위는
> 기획 과정에서 변경될 수 있으며, 변경 시 이 문서를 함께 갱신한다.

## 1. 제품 한 줄 정의

해커톤 아카이브는 과거 해커톤의 아이디어, 결과물, 평가와 후속 상태를 검색 가능한 자산으로 만들고,
중단된 프로젝트가 인수·협업·후원·계승을 통해 다시 이어지도록 돕는 AI 기반 프로젝트 순환 플랫폼이다.

## 2. 해결하려는 문제

### 아이디어와 시행착오의 반복

해커톤마다 비슷한 문제와 해결 방식이 반복되지만, 참가자는 과거에 어떤 아이디어가 제안됐고
어떤 평가를 받았으며 왜 중단됐는지 한곳에서 확인하기 어렵다. 그 결과 이미 여러 번 시도됐거나
경쟁력이 부족했던 접근을 처음부터 반복하게 된다.

### 대회 이후 프로젝트의 단절

수상작을 포함한 많은 프로젝트가 대회 종료 후 팀 일정 변화, 유지보수 인력 부족, 기술적 한계,
사용자 검증 실패, 사업화 역량 부족 등의 이유로 중단된다. 프로젝트가 멈춰도 코드, 디자인,
사용자 조사, 데이터와 문제 정의의 가치까지 사라지는 것은 아니다.

### 프로젝트를 이어받기 위한 정보의 부족

외부의 개인, 팀, 기업 또는 기관이 프로젝트를 이어가고 싶어도 구현 상태, 권리 범위,
기술 의존성, 남은 작업과 원작자가 제공할 수 있는 지원을 판단하기 어렵다.

## 3. 핵심 사용자

- 새로운 해커톤 아이디어를 검토하고 선행 사례를 찾는 참가자
- 자신이 만든 해커톤 프로젝트와 자료를 기록하려는 개인 또는 팀
- 중단된 프로젝트의 후속 개발자나 협업자를 찾는 프로젝트 소유자
- 기존 프로젝트를 인수하거나 계승해 발전시키려는 개발자와 참가팀
- 파일럿, 공동 개발 또는 라이선스 대상을 찾는 기업과 기관
- 특정 기능이나 지역 확장을 후원하고 싶은 일반 사용자

## 4. 핵심 가치 흐름

1. 프로젝트 소유자가 해커톤 결과물과 현재 상태를 등록한다.
2. 자료가 검색과 비교가 가능한 구조화된 프로젝트 기록으로 축적된다.
3. 사용자가 아이디어 또는 문제 상황을 입력하면 AI가 유사한 선행 프로젝트를 찾고 차이를 설명한다.
4. 사용자는 아이디어를 구체화하거나 기존 프로젝트와 협업·인수·계승하는 방향을 선택한다.
5. 중단된 프로젝트는 새로운 팀과 자원을 만나 후속 개발로 이어진다.

## 5. 프로젝트 기록

프로젝트는 최소한 다음 정보를 표현할 수 있어야 한다.

- 프로젝트명, 한 줄 소개, 해결하려는 문제와 대상 사용자
- 참가한 해커톤, 참가 시기, 팀 정보와 수상 기록
- 현재 상태와 상태 변경 이력
- 기술 스택, 구현 범위와 주요 의사결정
- 발표 자료, 데모 영상, 이미지, 사용자 조사 자료
- GitHub 저장소와 배포 링크
- 중단 이유, 미완성 기능, 알려진 기술적 한계
- 소유권, 라이선스, 공유 가능한 자산과 협업 가능 범위

### 프로젝트 상태 예시

- 아이디어 단계
- 개발 중
- 수상
- 후속 개발 중
- 일시 중단
- 인수·협업 모집
- 종료

상태 이름과 전환 규칙은 아직 확정된 정책이 아니다. 구현 시 단순 표시값으로 고정하기보다
도메인 정책이 정해진 뒤 확장할 수 있도록 설계한다.

## 6. 핵심 기능 후보

### 프로젝트 탐색과 검색

- 키워드, 문제 상황, 대상 사용자, 기술, 해커톤과 프로젝트 상태로 검색
- 카테고리, 아카이브 유형, 거래 또는 협업 방식, 수상 여부 등의 필터
- 인기 프로젝트, 최근 수상작과 후속 개발이 필요한 프로젝트 탐색

### AI 선행 사례 분석

사용자가 구상 중인 아이디어를 입력하면 AI가 축적된 프로젝트의 설명, 발표 자료,
기술 구조와 결과를 분석해 다음 정보를 제공한다.

- 유사한 문제를 다룬 프로젝트
- 기존 프로젝트가 사용한 해결 방식과 현재 상태
- 수상 여부와 중단 사유
- 사용자 아이디어와 선행 프로젝트의 공통점과 차이점
- 이미 반복된 접근과 새롭게 검증해야 할 가설
- 이어받거나 협업할 수 있는 프로젝트 후보

AI의 목적은 새로운 아이디어를 단순히 기각하는 것이 아니다. 선행 사례를 바탕으로 문제 범위를
좁히거나 차별점을 찾고, 기존 자산을 활용할 선택지를 제공하는 것이 목적이다.

### 인수·협업·계승 제안

프로젝트 소유자는 제공 가능한 범위를 직접 정한다.

- 전체 프로젝트 인수
- 비독점 라이선스
- 공동 개발
- 특정 코드 또는 기능 제공
- 오픈소스 전환
- 인수인계 및 기술 지원

제안은 단순한 아이디어 판매가 아니라 실제 이전 가능한 코드, 디자인, 데이터, 운영권,
라이선스와 지원 범위를 기준으로 해야 한다. 인수 금액과 계약 조건은 당사자가 결정한다.

### 팀원 모집

- 프로젝트별 필요한 역할과 기술을 명시한 팀원 모집
- 프론트엔드, 백엔드, AI/ML, UI/UX, PM 등 역할 기반 탐색
- 프로젝트 상태와 목표, 모집 인원, 마감 시점 확인
- 지원과 협업 제안

### AI 인수인계 지원

인수 또는 협업이 성사된 경우 기존 자료와 저장소를 바탕으로 다음 내용을 정리할 수 있다.

- 프로젝트 구조와 실행 방법
- 주요 의사결정과 기술 의존성
- 완료된 기능과 미완성 기능
- 알려진 문제와 후속 작업
- 권리와 라이선스 확인 항목

## 7. AI의 책임 범위

AI는 검색, 비교, 요약과 판단 보조 도구다.

AI가 할 수 있는 일:

- 유사 프로젝트 검색과 비교
- 프로젝트 자료 요약
- 공통점, 차이점과 검증 과제 제안
- 구현 상태, 기술 의존성과 후속 작업 정리
- 인수인계 문서 초안 생성

AI가 결정하면 안 되는 일:

- 프로젝트의 실제 소유권 확정
- 라이선스 적법성 보증
- 프로젝트나 아이디어의 가격 결정
- 거래 또는 협업 당사자를 대신한 계약 체결
- 근거 없이 수상 가능성이나 사업 성공을 보장하는 평가

AI 결과에는 근거가 된 프로젝트와 자료를 연결하고, 불확실한 내용은 추정임을 표시해야 한다.

## 8. 권리와 거래 원칙

- 프로젝트 등록자가 모든 자산을 양도할 권리를 가진다고 가정하지 않는다.
- 팀 공동 저작물, 대회 규정, 외부 데이터, 오픈소스 라이선스와 제3자 자료의 권리를 확인한다.
- 공개 가능한 자료와 협의 후 제공할 자료를 구분한다.
- 거래 또는 협업 전에 당사자가 권리 범위와 제공 자산을 명시적으로 확인해야 한다.
- AI 분석은 법률 검토나 권리 보증을 대체하지 않는다.

## 9. MVP 우선순위 초안

현재 제품의 중심 가치를 빠르게 검증하기 위한 우선순위다. 확정된 개발 일정은 아니다.

1. 프로젝트 등록과 상태 관리
2. 프로젝트 목록, 필터와 상세 조회
3. 키워드 및 문제 상황 기반 검색
4. AI 유사 프로젝트 비교와 요약
5. 중단 프로젝트의 협업 또는 인수 제안
6. 팀원 모집

실제 결제, 에스크로, 복잡한 계약 자동화와 권리 판정은 초기 MVP에서 바로 구현하기보다
수요와 정책을 먼저 검증한다.

## 10. 주요 화면 후보

- 홈: 서비스 설명, 통합 검색, 최근 수상작, 인기 프로젝트와 공모전 정보
- 아이디어 마켓 또는 프로젝트 탐색: 필터와 검색이 있는 프로젝트 목록
- 중단 프로젝트: 후속 개발, 인수 또는 협업이 필요한 프로젝트 목록
- 팀원 구하기: 역할 기반 모집 글 목록과 지원 흐름
- 프로젝트 상세: 소개, 단계별 자료, AI 분석, 팀 모집, Q&A와 소유자 정보
- AI 기획 도우미: 아이디어 입력, 선행 사례 비교와 검증 과제 확인
- 프로젝트 등록 및 수정
- 마이페이지: 내 프로젝트, 제안, 협업, 저장 목록과 계정 설정

화면명과 내비게이션 구조는 아직 확정되지 않았다. 초기 화면 구상은 `docs/wireframes.md`를 참고한다.

## 11. 제품 용어

- **프로젝트 아카이브**: 프로젝트 설명뿐 아니라 결과, 자료, 상태와 후속 이력까지 포함한 기록
- **중단 프로젝트**: 현재 개발이 이어지지 않지만 재사용하거나 계승할 자산이 남아 있는 프로젝트
- **계승**: 기존 프로젝트의 자산과 맥락을 이어받아 새로운 버전으로 발전시키는 활동
- **인수**: 합의된 권리와 자산을 다른 주체에게 이전하는 활동
- **협업 제안**: 소유권 전체 이전 없이 공동 개발, 기능 제공 또는 기술 지원을 제안하는 활동

내부 논의에서 `좀비 프로젝트`라는 표현을 사용할 수 있지만, 사용자 화면에서는 낙인처럼 느껴지지 않는
`중단 프로젝트`, `잠든 프로젝트` 또는 `후속 개발 프로젝트` 등의 표현을 우선 검토한다.

## 12. 참고 프로젝트 소재

다음 아이디어는 플랫폼이 특정 산업에 종속되지 않고 다양한 프로젝트를 다뤄야 한다는 참고 사례다.
각 아이디어의 상세 기능이 해커톤 아카이브 자체의 요구사항인 것은 아니다.

- SpacePop AI: 소상공인의 유휴 공간과 단기 팝업 수요 매칭
- MajorGig: 대학생 전공 기반 단기 일자리와 행사 매칭
- MAISON MEMORY: 럭셔리 제품의 디지털 오너십, 관리와 수선 경험
- FitRest AI: 운동 초보자의 운동 후 회복과 멘탈 케어
- Backup: 당일 대타 알바, 출퇴근 검증과 빠른 정산
- AI 체형 분석·가상 시착: 체형 분석, 의류 추천과 구매 전 시착

이 사례들은 검색, 상태, 기술, 권리, 협업 방식이 서로 다른 프로젝트를 데이터 모델이 수용할 수 있는지
검토하는 데 활용한다.

## 13. 현재 확정되지 않은 사항

- 서비스의 최종 명칭과 브랜드 디자인
- 프로젝트 상태의 최종 목록과 전환 규칙
- 판매, 기부, 후원, 라이선스와 공동 개발의 구체적인 계약 구조
- 결제 및 정산 방식
- 공개 자료와 비공개 자료의 접근 권한 정책
- AI 분석 모델, 검색 방식과 외부 데이터 연동 범위
- 사용자 신원, 수상 기록, 저장소 소유권의 검증 방식
- MVP에 포함할 화면과 우선순위의 최종 확정

위 항목은 코드나 UI에서 사실상 확정해 버리지 말고 기획 결정이 생기면 이 문서를 먼저 갱신한다.
