# 프로젝트 아카이브 제품 컨텍스트

> 문서 상태: 현재 제품 방향
>
> 이 문서는 제품 기능, 도메인 모델, 화면 구조와 UX 문구를 결정할 때 우선하는 기준이다.
> 세부 계약·요금·정산 수치는 별도 기획으로 확정하며, 확정된 프로젝트 상세 정보 정책은
> `docs/business-model.md`를 따른다. 정책 변경 시 이 문서를 함께 갱신한다.

## 1. 제품 한 줄 정의

프로젝트 아카이브는 공모전·대회·해커톤·캡스톤에서 만들어진 실제 출품 프로젝트를
검색 가능한 지식 자산으로 축적하고, AI 유사도 분석과 상세정보 열람·거래·팀원 모집을 통해
아이디어의 발생부터 재실행까지 연결하는 프로젝트 재활성화 플랫폼이다.

## 2. 해결하려는 문제

- 대회가 끝나면 출품작의 문제 정의, 해결 방식, 결과와 시행착오가 함께 사라진다.
- 이전 출품작을 찾기 어려워 이미 시도된 아이디어와 유사한 기획을 반복한다.
- 중단된 프로젝트의 코드·문서·디자인·데이터 등 남은 자산을 다시 활용하기 어렵다.
- 프로젝트를 다시 활용할 사람이 참고할 기획·디자인·개발 자료와 진행 맥락이 한곳에 남지 않는다.
- 일정, 관심 분야와 역량이 맞는 팀원을 프로젝트 단위로 찾기 어렵다.

초기 핵심 사용자는 대학생과 대학 연계 대회·공모전·캡스톤 참가자다. 이후 분야와
주최 기관을 확장하되 소프트웨어 프로젝트만을 전제로 데이터 모델이나 문구를 설계하지 않는다.

## 3. 등록 가능한 프로젝트

등록 대상은 공모전·대회·해커톤·캡스톤 등 외부 또는 교내 프로그램에 실제로 제출했던
프로젝트와 아이디어다. 수상 여부, 구현 기술과 완성도는 등록 자격이 아니다.

프로젝트는 최소한 다음 맥락을 표현할 수 있어야 한다.

- 프로젝트명, 한 줄 소개, 문제 정의, 대상 사용자와 해결 방식
- 출품한 행사, 주최 기관, 출품 시기, 분야와 수상 이력
- 아이디어·설계·초기 결과물·출품 결과물·실제 적용 등의 결과물 단계
- 진행 중·일시 중단·활동 종료 등의 현재 활동 상태와 상태 변경 이력
- 핵심 기능 또는 수행 방식, 기술·방법론과 검증 결과
- 기획서, 발표 자료, 코드, 디자인, 영상, 데이터 등 보유 자산
- 수행한 접근, 발생한 제약 조건, 확인된 한계, 중단·종료 사유와 후속 검증 과제
- 등록한 모든 정보와 자료가 서비스에 공개되는 것에 대한 공통 동의

## 4. 서로 다른 분류축

등록 목적과 현재 활동 상태를 같은 값이나 같은 탭으로 취급하지 않는다.

### 등록 목적

프로젝트당 현재 등록 목적은 하나만 선택한다. 목적은 추후 변경할 수 있다.

- `ZOMBIE`: 기본정보를 공개하고 1,000P 프로젝트 상세 정보 열람을 허용
- `SELL`: 등록한 프로젝트와 자료 전체를 희망 가격과 함께 판매
- `TEAM_RECRUIT`: 등록자가 프로젝트를 계속 주도하며 팀원을 모집

기존 `ARCHIVE`와 `REGISTER`는 `ZOMBIE`로 통합한다. `SELL`은 유상 판매만 다루며 프로젝트
상세 정보 열람과 프로젝트 판매는 별개의 거래다. 등록 목적은 활동 상태를 대신하지 않는다.

### 현재 활동 상태와 결과물 단계

- 현재 활동 상태는 진행 중, 일시 중단, 활동 종료처럼 현재 진행 여부를 나타낸다.
- 결과물 단계는 아이디어·기획, 구체화·설계, 초기 결과물, 출품 결과물,
  실제 적용·운영처럼 출품 당시 확인 가능한 결과 수준을 나타낸다.
- `개발 상태`, `MVP` 같은 소프트웨어 중심 표현을 전체 프로젝트의 공통 분류명으로 사용하지 않는다.
  앱, 제품, 연구, 캠페인, 전시 등 분야별 표현은 결과물 단계의 설명 예시로만 제공한다.
- 일시 중단된 프로젝트가 자동으로 좀비 프로젝트가 되지 않는다.
- 진행 중단 여부만으로 공개, 사용 허락이나 권리 이전 의사를 추정하지 않는다.

## 5. 좀비 프로젝트

좀비 프로젝트는 활동 상태와 무관하게 프로젝트의 기본 기록을 공개하고, 다른 사용자가
프로젝트 상세 정보를 유료로 열람할 수 있게 등록한 프로젝트다.

- 프로젝트명, 100자 공개 소개, 출품 맥락, 결과물 단계, 활동 상태와 자산 종류·개수만 무료로 공개한다.
- 문제 상황, 해결 방법, 핵심 기능, 검증 결과, 제약·한계와 자산명·파일·링크는 1,000P 열람 후 공개한다.
- 열람 권한은 구매한 사용자에게만 적용하며 자산의 사용권이나 소유권을 제공하지 않는다.
- 자산이 없는 프로젝트도 등록할 수 있고, 공개 재사용 자산이나 라이선스 입력을 필수로 요구하지 않는다.

## 6. 핵심 기능

### 프로젝트 탐색

- 전체 출품작을 키워드, 행사, 연도, 분야, 문제 영역, 기술·방법, 결과물 단계와 활동 상태로 탐색
- 기본 메타데이터와 등록 목적을 확인하고 프로젝트 상세 정보로 진입
- 인기 프로젝트, 최근 수상작과 신규 등록 프로젝트 확인

#### 목록 카드 공개 정보 계약

홈의 인기·최근 수상작, 프로젝트 탐색, AI 검색, 좀비 프로젝트, 프로젝트 마켓과 팀원 모집은
등록 과정에서 받은 정보를 서로 다른 임시 응답 모양에 맞춰 임의로 축약하지 않는다. 모든 프로젝트
목록은 다음 공통 요약 정보를 같은 의미로 제공해야 한다.

- 프로젝트 ID, 프로젝트명, 공개 한 줄 소개와 선택형 대표 이미지
- 등록 목적, 출품 행사·출품 연도와 등록일
- 분야·문제 영역·기술 또는 수행 방법·사용자 정의 태그
- 결과물 단계, 현재 활동 상태
- 보유 자산 개수와 자산 유형 요약
- 자기기입 수상 이력 요약
- 정보 충실도와 조회·좋아요·저장 등의 실제 통계

대표 이미지가 없는 프로젝트도 정상적으로 목록에 노출하며 이미지 미등록 상태를 명확히 표시한다.
목록에서 문제 정의 전문, 상세 해결 과정, 검증 자료, 제약·한계와 자산명·파일·링크 등
프로젝트 상세 정보 내용을 미리 공개하지 않는다.

등록 목적별 목록에는 공통 정보에 더해 다음 공개 요약을 제공한다.

- 프로젝트 마켓: 희망 판매가, 가격 조건과 등록 자료 종류·개수
- 좀비 프로젝트: 공통 열람가 1,000P와 상세정보 열람 시 콘텐츠 정산 포인트가 발생한다는 안내
- 팀원 모집: 모집글 ID와 프로젝트 ID의 연결, 모집 역할·인원·마감일·필요 역량·일정·진행 방식,
  지원자가 확인할 수 있는 참고 자산
- AI 프로젝트 검색: 유사도, 유사한 이유, 주요 차이점과 추가 검증 과제

현재 개별 목록 API에 필드가 없으면 프론트엔드는 카드 구조를 유지하고 값을 `연동 전` 또는
`미산정`으로 표시한다. 해당 목록 영역에는 `백엔드 미구현`과 필요한 계약 범위를 한 번만 설명하며,
가짜 값이나 클라이언트 계산으로 채우지 않는다. 상세 화면은 별도 작업 범위이며 존재하지 않는
상세 경로로 연결하지 않는다.

### AI 프로젝트 검색

사용자의 아이디어에서 문제 정의, 대상 사용자, 해결 방식, 핵심 기능과 서비스 형태를 분석해
유사한 기존 프로젝트를 찾는다. 단순 일치 목록이 아니라 유사도 근거, 공통점, 차이점과
추가 검증 과제를 함께 제공한다.

### 좀비 프로젝트

기본정보를 탐색하고 필요할 때 프로젝트 상세 정보를 열람해 기존 접근과 한계를 확인한다.

### 프로젝트 마켓

등록자가 프로젝트에 남은 기획·문서·디자인·코드·데이터 등의 자료를 함께 등록하고 희망 가격을
설정한다. 자료를 다시 선택하거나 자료마다 별도 공개·권리 조건을 입력하지 않으며, 등록한
프로젝트와 자료 전체를 하나의 판매 단위로 취급한다.

### 팀원 모집

프로젝트 또는 참가 예정 대회를 기준으로 필요한 역할, 기술, 일정, 관심 분야와 모집 마감일을
표시하고 프로젝트 단위로 팀을 만든다.

## 7. 정보 접근과 BM

기본 메타데이터와 100자 공개 소개는 공개하고, 프로젝트 상세 정보는 목적별 권한으로 열람하는
지식 아카이브 모델을 사용한다. AI 검색은 요금제별 기본 제공량과 추가 토큰을 사용한다.

상세정보 구매는 정보 열람권만 제공한다. 코드·디자인·데이터·IP의 사용권이나 소유권은
자동으로 포함되지 않는다. 상세 정책은 `docs/business-model.md`를 따른다.

해커톤 데모의 좀비 프로젝트 상세 정보 열람가는 `1,000P`로 동일하다. 프로젝트별
상세정보 가격 입력은 허용하지 않으며, 프로젝트 마켓의 프로젝트 판매가는 별도의 가변
가격으로 유지한다. 정보 충실도는 열람가가 아니라 등록자와 플랫폼의 콘텐츠 정산 배분율에만
영향을 준다.

## 8. AI와 정보 충실도 평가

AI는 검색, 비교, 요약과 등록 정보의 충실도 점검을 돕는다. 다음 사항을 확정하거나 보증하지 않는다.

- 실제 소유권과 라이선스 적법성
- 프로젝트나 아이디어의 가격
- 거래 당사자를 대신한 계약
- 근거 없는 사업 성공 또는 수상 가능성

### 제품 용어: 정보 충실도

프로젝트 카드와 상세 화면에서 사용하는 공식 명칭은 `정보 충실도`다. `프로젝트 완성도`는
아이디어·프로토타입·MVP·완성작 같은 완성 수준과 혼동되고, `프로젝트 품질`은 성공 가능성이나
우수성을 평가하는 표현으로 오해될 수 있으므로 사용하지 않는다.

정보 충실도는 사용자가 프로젝트 상세 정보를 열기 전에 등록 정보가 판단에 필요한 맥락을 충분히
제공하는지 확인하는 0~100점 보조 지표다. 다음 요소를 기반으로 산정한다.

- 문제 정의, 대상 사용자, 해결 방식과 핵심 기능의 구체성
- 출품 행사, 주최 기관, 시기와 자기기입 수상 이력의 구체성
- 구현 결과, 검증 방법과 결과에 대한 설명
- 보유 자료의 종류, 프로젝트에서의 역할과 내용 설명
- 수행한 접근, 제약 조건, 중단·종료 사유, 확인된 한계와 후속 검증 과제 기록

점수는 결과물 단계, AI 유사도, 시장 가치, 사업 성공 가능성이나 작품의 우수성을 의미하지
않는다. 카드에는 숫자와 단일 막대만 표시하며 근거가 확정되지 않은 `우수`, `부족` 등의 등급은
붙이지 않는다. 점수가 아직 산정되지 않은 프로젝트는 0점으로 처리하지 않고 `미산정`으로 표시한다.

AI 점수만으로 등록자에게 보상을 선지급하지 않는다. 실제 유료 열람이 발생할 때만 판매
상세정보 버전에 저장된 정보 충실도 snapshot으로 콘텐츠 정산 포인트를 계산한다. 정산 정책은
`INFO_COMPLETENESS_LINEAR_V1`이며 등록자 비율은 0점·미산정의 60%에서 100점의 90%까지
선형으로 증가한다. `null`은 0점으로 바꾸지 않고 `미산정`으로 유지하되 기본 정산율 60%를
적용한다.

### 추후 백엔드 이슈에 포함할 계약 요구사항

프론트엔드의 프로젝트 탐색, 키워드 검색, AI 검색, 좀비 프로젝트와 프로젝트 마켓 목록이 동일한
정보 충실도 값을 표시할 수 있어야 한다. 백엔드 저장소 점검 후 기능 단위 이슈를 작성할 때 다음을
반드시 포함한다.

- 모든 프로젝트 요약 응답에 `informationCompletenessScore: integer | null`을 제공하고 0~100 범위를 보장
- 미산정 상태는 `null`로 반환하며 누락값이나 0점으로 대체하지 않음
- 점수 산정 시각과 산정 규칙 버전을 추적할 수 있도록
  `informationCompletenessEvaluatedAt`, `informationCompletenessVersion` 제공 검토
- 등록 정보가 변경되었을 때 재산정하는 시점과 실패·대기 상태 정의
- 프로젝트 상세 응답에서 항목별 점수와 보완이 필요한 입력을 제공하는 breakdown 계약 검토
- 같은 프로젝트가 일반 탐색·AI 검색·좀비·마켓에 노출될 때 동일한 최신 점수를 반환
- 점수 산정 기준과 가중치 변경 시 기존 프로젝트 재산정 및 버전 호환 정책 정의

### 자산을 포함한 정보 충실도 평가 원칙

프로젝트 자료는 파일 개수가 아니라 프로젝트 설명과의 연결, 활용 가능한 맥락과 설명의 구체성을
평가한다. 소프트웨어 프로젝트가 아닌 디자인, 연구, 제품, 캠페인과 전시
프로젝트가 특정 파일 형식이나 GitHub 저장소가 없다는 이유로 불이익을 받아서는 안 된다.

- 기획·문서: PDF, DOC/DOCX, HWP/HWPX, PPT/PPTX와 문서 링크
- 디자인: Figma 링크, FIG·Sketch·XD 원본, PDF·SVG·이미지
- 코드·기술: GitHub·GitLab 저장소, 배포 링크와 압축 파일
- 데이터·연구: CSV·XLSX·JSON, 조사·설문·실험 자료와 결과 문서
- 영상·오프라인 결과물: 시연 영상, 사진, 제작 과정과 전시·발표 자료
- 기타: 프로젝트 분야에 맞는 파일 또는 외부 링크와 직접 설명

하나의 논리적 자산에는 원본 파일과 외부 작업 링크를 함께 연결할 수 있다. AI는 다음 항목을
프로젝트 분야, 결과물 단계와 등록 목적에 맞춰 평가한다.

- 프로젝트 설명과 자산 내용·역할이 실제로 연결되는지
- 선택한 분야와 결과물 단계에 적절한 근거인지
- 자산의 내용과 다른 사용자가 활용할 방법이 설명되어 있는지
- 파일·링크가 프로젝트 설명과 연결되고 실제로 확인 가능한지
- 검증 결과, 확인된 제약·한계와 후속 검증 과제가 자산으로 뒷받침되는지
- 좀비 상세정보, 프로젝트 판매 또는 모집 참고자료 등 선택한 목적의 조건을 충족하는지

파일 한 개당 단순 가산, 중복 파일 등록, 파일 크기, 특정 확장자 보유 여부는 점수 근거로 사용하지
않는다. AI는 시장성, 작품의 우수성, 수상 가능성과 실제 권리 적법성을 평가하거나 보증하지 않는다.

백엔드 이슈에는 파일·링크 메타데이터와 함께 항목별 평가 근거, 우선 보완 항목, 규칙 버전,
평가 시각, 재평가 상태와 중복 자산 처리 기준을 포함한다. HWP/HWPX·Office·PDF·이미지·데이터
문서 파싱, GitHub·Figma·Notion·영상 링크 판별과 접근 확인도 별도 기능
단위로 검토한다.

## 9. 자료 공개와 거래 원칙

- 등록 화면에서는 자료별 공개 범위, 소유 상태, 사용 권한과 권리 범위를 입력받지 않는다.
- 마지막 단계에서 등록한 모든 정보와 자료가 서비스에 공개되는 것에 한 번만 동의한다.
- 첨부 파일과 외부 링크도 같은 동의 대상이며 자료마다 별도 공개 조건을 두지 않는다.
- 공개 동의는 해당 자료의 저작권 보유나 판매 시 권리 이전을 자동으로 증명하지 않는다.
- 프로젝트 판매의 계약·권리 확인과 분쟁 처리 방식은 등록 폼과 분리해 추후 거래 정책으로 확정한다.

## 10. 주요 화면과 내비게이션

상단 주요 메뉴는 다음 세 기능을 직접 노출한다.

1. 프로젝트 탐색
2. AI 프로젝트 검색
3. 팀원 모집

프로젝트 탐색은 모든 프로젝트를 검색·비교하는 상위 허브이며 다음 보기를 제공한다.

- 전체 프로젝트
- 좀비 프로젝트: 기본정보를 탐색하고 프로젝트 상세 정보를 열람할 수 있는 프로젝트
- 판매 중인 프로젝트: 등록한 프로젝트 자료 전체와 희망 가격을 공개한 프로젝트

좀비 프로젝트와 프로젝트 마켓은 직접 진입 가능한 URL을 유지하더라도 상단 메뉴에서는 프로젝트
탐색의 하위 보기로 표현한다. `좀비 프로젝트`는 단순 활동 중단 상태를 뜻하지 않으며, 상세정보
열람 목적으로 등록한 프로젝트만 포함한다. 팀원 모집은 모집 역할·인원·마감일·지원 상태와 별도 지원 흐름이
필요하므로 프로젝트 보기와 합치지 않고 독립 메뉴로 유지한다.

## 11. 프로젝트 등록 화면을 만들 때의 기준

프로젝트 등록은 다음 여섯 단계로 진행한다.

1. 출품 행사·연도·주최 기관과 자기기입 수상 이력
2. 프로젝트명, 공개 한 줄 소개, 선택형 대표 이미지와 구조화 태그
3. 문제 정의, 대상, 해결 방식, 결과물 단계와 현재 활동 상태
4. 수행한 접근·제약 조건·확인된 한계·후속 검증 과제와 파일·외부 링크 기반 보유 자산
5. `ZOMBIE | SELL | TEAM_RECRUIT` 중 등록 목적과 목적별 조건
6. 공개 카드·정보 충실도 검토와 전체 등록 자료 공개 동의

수상 이력은 이력서처럼 사용자가 행사명, 수상명과 수상일을 직접 입력하며 별도 증빙을 요구하지
않는다. 공개된 프로젝트는 수상 이력이 있으면 최근 수상작 후보에 포함한다.

자료별 공개 범위, 소유 상태, 사용 권한과 권리 범위는 입력받지 않는다. 등록한 모든 정보와
첨부 파일·외부 링크의 서비스 공개에 동의해야 최종 등록할 수 있다.

장기 작성 폼의 텍스트, 선택값과 외부 링크는 브라우저에 자동 임시 저장한다. 파일은 보안과 용량
문제로 브라우저 저장에 포함하지 않고 새로고침 후 재첨부를 안내한다. 정보 충실도는 마지막 단계에서
AI 점검 후에만 표시하며, 점수는 등록을 차단하지 않는다.

## 12. 아직 확정하지 않은 사항

- 구독 요금, AI 토큰 가격과 월 제공량
- 현금 출금·포인트 환산·실결제 수단과 실제 지급 정산
- 콘텐츠 정산의 부정 이용 탐지와 분쟁 처리 세부 절차
- 프로젝트 판매의 계약, 결제, 에스크로와 분쟁 처리
- 프로젝트 판매 단계의 계약·권리 확인 절차
- 프로젝트 상태의 최종 enum과 전환 규칙
- 사용자 신원, 출품·수상 기록과 저장소 소유권 검증 방식

위 항목은 가짜 동작이나 임의의 수치로 UI에서 확정하지 않는다.
