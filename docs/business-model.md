# 프로젝트 아카이브 BM과 자료 공개

> 문서 상태: 제품 방향 및 프로젝트 상세 정보 데모 포인트 가격·정산 정책 확정

## 1. 기본 구조

프로젝트 아카이브의 기본 BM은 논문 아카이브처럼 검색 가능한 메타데이터를 공개하고,
상세 프로젝트 지식과 AI 분석에 구독 또는 이용량 기반 과금을 적용하는 구조다.

- 공개: 프로젝트명, 초록, 출품 정보, 분야, 결과물 단계, 현재 활동 상태
- 권한 필요: 상세 문제 정의, 해결 과정, 검증 자료, 제약·한계, 자산명·파일·링크
- 사용량 기반: AI 유사 프로젝트 검색과 상세 분석
- 별도 거래: 프로젝트 마켓의 프로젝트·등록 자료 판매

## 2. 프로젝트 상세 정보 열람

- 좀비 프로젝트의 상세정보 결제는 구매자 개인의 정보 열람권만 제공한다.
- 해커톤 데모의 좀비 프로젝트 상세 정보 열람가는 `1,000P`로 동일하다.
- 프로젝트별 상세정보 가격 입력·수정은 허용하지 않는다.
- 프로젝트 자산의 사용, 복제, 배포, 상업화 또는 소유권 이전 권한을 자동으로 제공하지 않는다.
- 판매 프로젝트는 프로젝트 구매 후 새 소유자에게만 상세정보와 자산을 공개하며 별도 열람 상품을 만들지 않는다.
- 팀원 모집에 필요한 역할·일정·지원 조건은 지원자가 결제하지 않아도 확인할 수 있어야 한다.
- 팀원 모집 프로젝트의 일반 상세정보와 자산은 프로젝트 소유자만 확인한다.

## 3. AI 검색 토큰

- 요금제마다 일정한 AI 검색 기본 제공량을 둔다.
- 제공량을 넘은 검색은 추가 토큰을 사용한다.
- UI에는 남은 이용량과 초기화 시점을 표시할 자리를 마련한다.
- 실제 제공량, 차감 기준과 결제는 정책 및 백엔드 계약이 확정되기 전까지 동작시키지 않는다.

## 4. 등록자 정산

등록자가 충실한 프로젝트 정보를 제공할 유인을 만들기 위해 좀비 프로젝트 상세 정보 열람 수익
일부를 콘텐츠 정산 포인트로 배분한다.

- 정산 정책 코드는 `INFO_COMPLETENESS_LINEAR_V1`이다.
- 정보 충실도는 1,000P 열람가를 바꾸지 않고 등록자·플랫폼 배분율만 바꾼다.
- AI 정보 충실도 점수만으로 보상을 선지급하지 않고 실제 유료 열람이 발생할 때만 정산한다.
- 점수 `null`은 0점으로 바꾸지 않고 `미산정`으로 유지하되 기본 정산율 60%를 적용한다.
- `수수료 지급`이 아니라 `콘텐츠 정산` 또는 `기여 보상`으로 표현한다.

| 정보 충실도 | 등록자 비율 | 등록자 정산 | 플랫폼 몫 |
|---:|---:|---:|---:|
| 미산정 | 60% | 600P | 400P |
| 0점 | 60% | 600P | 400P |
| 20점 | 66% | 660P | 340P |
| 40점 | 72% | 720P | 280P |
| 60점 | 78% | 780P | 220P |
| 80점 | 84% | 840P | 160P |
| 100점 | 90% | 900P | 100P |

```text
creatorRevenueBps = 6000 + informationCompletenessScore × 30
creatorRevenuePoint = floor(1000 × creatorRevenueBps / 10000)
platformFeePoint = 1000 - creatorRevenuePoint
```

- 특정 상세정보 버전이 처음 판매될 때 점수·평가 규칙 버전·평가 시각·정산율을 snapshot한다.
- 같은 상세정보 버전의 일시중지·재판매에는 기존 snapshot을 사용하고 새 버전만 최신 점수로 다시 계산한다.
- 구매 시점의 현재 프로젝트 소유자에게 정산하며 양도 전 거래는 이전 소유자의 기록으로 남긴다.
- 환불은 구매 당시 등록자 정산액과 플랫폼 몫을 같은 snapshot으로 역분개한다.
- 완료된 과거 구매·정산 금액을 새 가격이나 정산율로 소급 변경하지 않는다.

현금 최소 지급액, 출금·환산과 부정 이용·분쟁 처리 세부 절차는 이 데모 포인트 정책의 범위 밖이다.

## 5. 프로젝트 마켓과의 구분

| 구분 | 프로젝트 상세 정보 열람 | 프로젝트 판매 |
| --- | --- | --- |
| 구매 대상 | 구조화된 프로젝트 정보 | 등록한 프로젝트와 자료 전체 |
| 독점성 | 비독점 | 거래 정책 확정 전 |
| 소유권 이전 | 없음 | 거래 정책 확정 전 |
| 반복 판매 | 여러 사용자가 열람 가능 | 일반적으로 특정 상대와 한 번 체결 |
| 플랫폼 수익 | 구독·이용권 | 거래 수수료 또는 중개 수익 |

두 거래를 하나의 `구매하기` 버튼이나 같은 가격으로 표현하지 않는다.

기존 아카이브 등록은 좀비 프로젝트로 통합한다. 좀비 프로젝트는 기본정보만 무료 공개하고,
자산명·파일·링크를 포함한 상세정보는 열람권 구매 후 제공한다.

프로젝트 등록 화면에서는 자료별 공개 범위, 소유 상태, 사용 권한과 권리 범위를 입력받지 않는다.
마지막 단계에서 등록한 모든 정보와 자료의 서비스 공개에 한 번만 동의한다. 이 동의는 프로젝트
판매 시 저작권이나 소유권 이전을 자동으로 확정하는 계약이 아니며, 해당 정책은 별도로 확정한다.

## 6. 해커톤 데모 포인트

- 데모에서는 마이페이지에서 충전한 포인트로 유료 기능과 프로젝트 판매를 결제한다.
- 프로젝트 등록자는 **프로젝트 판매가**만 포인트 단위로 입력한다. 프로젝트 상세 정보 열람가는 입력하지 않는다.
- 프로젝트 상세 정보와 정산 화면에는 다음 안내를 같은 문구로 표시한다.

  ```text
  좀비 프로젝트의 상세 정보 열람가는 1,000P로 동일합니다.
  정보 충실도가 높을수록 등록자에게 배분되는 콘텐츠 정산 비율이 높아집니다.
  현재 포인트는 데모용이며, 실서비스에서는 추가 결제수단이 제공될 예정입니다.
  ```

- 계좌번호, 카드 정보와 실제 결제수단은 프로젝트 등록 단계에서 받지 않는다.
- 프로젝트 상세 정보 포인트 환불은 구매 당시 snapshot을 정확히 역분개한다.
- 포인트 환산율, 현금 출금·지급과 실서비스 결제수단은 확정하지 않으며 가짜 동작이나 임의 수치로
  구현하지 않는다.
