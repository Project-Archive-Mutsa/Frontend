# 프로젝트 아카이브 BM과 접근 권한

> 문서 상태: 제품 방향 확정, 가격·정산 수치 미확정

## 1. 기본 구조

프로젝트 아카이브의 기본 BM은 논문 아카이브처럼 검색 가능한 메타데이터를 공개하고,
상세 프로젝트 지식과 AI 분석에 구독 또는 이용량 기반 과금을 적용하는 구조다.

- 공개: 프로젝트명, 초록, 출품 정보, 분야, 결과물 단계, 현재 활동 상태
- 구독 전용: 상세 문제 정의, 해결 과정, 검증 자료, 실패·중단 기록, AI 비교와 인수인계 리포트
- 사용량 기반: AI 유사 프로젝트 검색과 상세 분석
- 별도 거래: 프로젝트 마켓의 자산·권리 판매

## 2. 상세 리포트 열람

- 상세 리포트 결제는 정보 열람권만 제공한다.
- 프로젝트 자산의 사용, 복제, 배포, 상업화 또는 소유권 이전 권한을 자동으로 제공하지 않는다.
- 좀비 프로젝트의 공개 재사용 자산은 상세 리포트와 별도이며, 해당 자산의 라이선스를 따른다.
- 팀원 모집에 필요한 역할·일정·지원 조건은 지원자가 결제하지 않아도 확인할 수 있어야 한다.

## 3. AI 검색 토큰

- 요금제마다 일정한 AI 검색 기본 제공량을 둔다.
- 제공량을 넘은 검색은 추가 토큰을 사용한다.
- UI에는 남은 이용량과 초기화 시점을 표시할 자리를 마련한다.
- 실제 제공량, 차감 기준과 결제는 정책 및 백엔드 계약이 확정되기 전까지 동작시키지 않는다.

## 4. 등록자 정산

등록자가 충실한 프로젝트 정보를 제공할 유인을 만들기 위해 상세 리포트 이용 수익 일부를
콘텐츠 정산금으로 배분한다.

- AI는 정보 충실도, 구체성, 자산 설명과 시행착오 기록을 점검한다.
- AI 품질 점수만으로 보상을 선지급하지 않는다.
- 실제 열람, 이용자의 유용성 평가와 부정 이용 검증을 함께 반영한다.
- `수수료 지급`이 아니라 `콘텐츠 정산` 또는 `기여 보상`으로 표현한다.

구체적인 정산식, 최소 지급액과 부정 이용 정책은 별도로 확정한다.

## 5. 프로젝트 마켓과의 구분

| 구분 | 상세 리포트 열람 | 프로젝트 판매 |
| --- | --- | --- |
| 구매 대상 | 구조화된 프로젝트 정보 | 명시된 자산과 권리 |
| 독점성 | 비독점 | 계약에 따라 양도 또는 독점 가능 |
| 소유권 이전 | 없음 | 계약 범위에 따라 있음 |
| 반복 판매 | 여러 사용자가 열람 가능 | 일반적으로 특정 상대와 한 번 체결 |
| 플랫폼 수익 | 구독·이용권 | 거래 수수료 또는 중개 수익 |

두 거래를 하나의 `구매하기` 버튼이나 같은 가격으로 표현하지 않는다.

금전 거래 없는 기록과 공유는 프로젝트 마켓의 거래 유형으로 다루지 않는다. 재사용을 허용하지
않는 기록은 아카이브 등록, 자산을 조건과 함께 무상 공개하는 경우는 좀비 프로젝트 정책을 따른다.

## 6. 해커톤 데모 포인트

- 데모에서는 마이페이지에서 충전한 포인트로 유료 기능과 프로젝트 판매를 결제한다.
- 프로젝트 등록자는 판매 희망가를 포인트 단위로 입력한다.
- 등록 화면과 향후 충전 화면에는
  `데모 버전에서는 충전 포인트로 거래합니다. 실서비스에서는 추가 결제수단이 제공될 예정입니다.`를
  표시한다.
- 계좌번호, 카드 정보와 실제 결제수단은 프로젝트 등록 단계에서 받지 않는다.
- 포인트 환산율, 환불, 정산과 실서비스 결제수단은 아직 확정하지 않으며 가짜 동작이나 임의 수치로
  구현하지 않는다.
